TESTING CHECKLIST: 11 items
Automatic checks that catch mistakes before people see them.
Backing: 1 Rule, 6 Standard, 0 Research, 4 Practice
Rule = a store or a law requires it · Standard = a published standard · Research = usability studies · Practice = good practice, no study found

SHAPE
 1. Many small unit tests, fewer integration tests, few end-to-end tests   (Standard: fowler-test-pyramid)
 2. Contract tests for APIs between services   (Standard: fowler-test-pyramid)

WHAT
 3. Every bug fixed gets a test that would have caught it   (Practice)
 4. Permission tests for each role, including refused cases   (Standard: owasp-asvs)
 5. Edge cases: empty, very long, Arabic and right-to-left text, time zones   (Practice)  -> see design-system/rtl-localisation, backend/dates-money
 6. Accessibility checks on key screens   (Standard: wcag)

RUNNING
 7. Tests run on every change and block merging when they fail   (Standard: sre-release)
 8. Flaky tests fixed or removed, not ignored   (Practice)
 9. Tests use their own data and clean up after themselves   (Practice)

DATA
10. No real personal data in test environments   (Rule: gdpr-5)  -> see backend/data-privacy, operations/environments

SECURITY
11. Dependency and code scanning in the pipeline   (Standard: owasp-dependencies, nist-ssdf)  -> see operations/dependencies
