ERROR HANDLING IN CODE CHECKLIST: 8 items
What code does when something fails, so people see help and developers see the cause.
Backing: 0 Rule, 7 Standard, 1 Research, 0 Practice
Rule = a store or a law requires it · Standard = a published standard · Research = usability studies · Practice = good practice, no study found

CATCHING
 1. Expected failures (network, invalid input) handled where they happen   (Standard: owasp-errors)
 2. An error boundary around each screen so one crash does not blank the app   (Standard: react-error)
 3. Errors never swallowed silently   (Standard: owasp-errors)

SHOWING
 4. People see plain words and a next step, never raw error text   (Research: nng-errors)  -> see design-system/content-voice
 5. Retry offered for temporary failures, with growing waits   (Standard: aws-backoff)

RECORDING
 6. Every unexpected error logged with context and a request id   (Standard: owasp-logging, otel)  -> see operations/logging
 7. No passwords or personal data in error reports   (Standard: owasp-logging)  -> see backend/data-privacy

SAFETY
 8. Failures fail closed: access denied when a check errors   (Standard: owasp-scp)
