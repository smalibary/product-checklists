Saving work in git so history explains itself and the main version stays working.
Backing: 0 Rule, 8 Standard, 0 Research, 0 Practice

COMMITS
 1. One logical change per commit   (Standard: git-book)
 2. A short summary line, then why it changed   (Standard: git-book)
 3. A shared message format (feat, fix, docs) when release notes are generated   (Standard: conv-commits)
 4. No secrets, built files or huge data in commits   (Standard: owasp-secrets)

BRANCHES
 5. Main always works; work happens on short-lived branches   (Standard: github-flow)
 6. Branches merged through a reviewed pull request   (Standard: github-flow)
 7. Release versions tagged with version numbers   (Standard: semver)

HISTORY
 8. Breaking changes marked in the commit and release notes   (Standard: conv-commits, semver)
