RESETTING PASSWORD (FLOW) CHECKLIST: 19 items
Getting back into an account after forgetting the password.
Backing: 0 Rule, 14 Standard, 2 Research, 3 Practice
Rule = a store or a law requires it · Standard = a published standard · Research = usability studies · Practice = good practice, no study found

STARTING
 1. "Forgot password?" next to the password field   (Research: nng-password)
 2. Email field filled with what was typed on login   (Practice)  -> see web-app/login
 3. Same message whether or not the account exists ("If an account exists, we sent a link")   (Standard: owasp-forgot)

THE LINK OR CODE
 4. Random, single use, expires soon (about an hour or less)   (Standard: owasp-forgot)
 5. Sent by email, or code by SMS where that is how people sign in   (Standard: owasp-forgot)  -> see web-app/login
 6. Resend after a short wait   (Standard: owasp-auth)
 7. Link opens on any device   (Practice)

NEW PASSWORD
 8. One field with Show, not two to match   (Research: nng-password)
 9. Rules shown up front, checked as typed: at least 8 characters (15 if password-only), no forced mix of symbols   (Standard: nist-63b)
10. Common or leaked passwords refused with a reason   (Standard: nist-63b)
11. Password managers can fill and save (autocomplete new-password)   (Standard: mdn-autocomplete)

AFTER
12. Signed in, or sent to login with a success message   (Practice)
13. Other sessions signed out, with the choice shown   (Standard: owasp-session)  -> see backend/sessions
14. Email telling the person the password changed, with "This wasn't me"   (Standard: owasp-forgot)

SECURITY
15. Requests rate-limited   (Standard: owasp-auth)  -> see api/rate-limits
16. Two-step check still asked if it was on   (Standard: owasp-mfa)  -> see flows/setting-up-two-step
17. No security questions   (Standard: nist-63b)

ACCESS
18. Fields named; no time pressure   (Standard: wcag-labels, wcag-timing)  -> see design-system/accessibility
19. Copy-paste allowed   (Standard: wcag-auth)
