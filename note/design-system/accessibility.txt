ACCESSIBILITY CHECKLIST: 31 items
What every page and screen needs so people with disabilities can use it. Other checklists point here instead of repeating it.
Backing: 1 Rule, 26 Standard, 1 Research, 3 Practice
Rule = a store or a law requires it · Standard = a published standard · Research = usability studies · Practice = good practice, no study found

TARGET AND LAW
 1. Aim at WCAG 2.2 level AA for every component   (Standard: wcag)
 2. Laws that require it: the European Accessibility Act from June 2025, the ADA in the US   (Rule: eu-accessibility-act, ada-web)
 3. Each component's page states its accessibility support and known gaps   (Practice)

COLOUR AND CONTRAST
 4. Text 4.5:1, large text 3:1, borders and icons of controls 3:1   (Standard: wcag-contrast, wcag-ui-contrast)
 5. Colour never the only way to show state or meaning   (Standard: wcag-color)
 6. Focus ring visible with 3:1 contrast in every theme   (Standard: wcag-focus-appearance)
 7. Light, dark and high-contrast themes all checked   (Standard: mdn-color-scheme)

KEYBOARD AND FOCUS
 8. Every interactive part reachable and usable by keyboard   (Standard: wcag-keyboard)
 9. Keyboard behaviour follows the ARIA patterns (arrows in menus, tabs, radios)   (Standard: apg)  -> see design-system/tabs, design-system/radio
10. Focus order follows reading order   (Standard: wcag-focus-order)
11. Focused things are never hidden behind sticky headers   (Standard: wcag-obscured)  -> see website/header
12. Skip link to the main content   (Standard: wcag-bypass)

NAMES AND ROLES
13. Native HTML elements first; ARIA only when needed   (Standard: apg)
14. Every control has a name, role and state   (Standard: wcag-name-role)
15. Icon-only buttons have a text name   (Standard: wcag-name-role)  -> see design-system/icon
16. Status messages announced without moving focus   (Standard: wcag-status)

TOUCH AND MOTION
17. Targets at least 24 by 24 px on the web (44 recommended); 44 pt on iPhone, 48 dp on Android   (Standard: wcag-target, hig-layout, m3-layout)
18. Dragging always has a single-tap alternative   (Standard: wcag-dragging)
19. Reduced motion respected; nothing flashes more than 3 times a second   (Standard: mdn-reduced-motion, wcag-flash)  -> see motion/motion-accessibility

PAGES
20. Each page has a title that names it and the site ("Sign in · Qanat Books")   (Standard: wcag-title)  -> see web-app/login
21. One main heading, and headings in order so the page reads as an outline   (Standard: wcag-headings)
22. Works at phone width (320 px) with no sideways scrolling   (Standard: wcag-reflow)
23. Text can be enlarged to 200% without cutting anything off   (Standard: wcag-resize)
24. Phone apps support large system text; rows grow instead of cutting text   (Standard: hig-accessibility)
25. Every flow works start to finish by keyboard alone and with a screen reader   (Standard: wcag-keyboard)

CONTENT
26. Pictures that tell something have alt text; decorative ones are hidden from screen readers   (Standard: wcag-nontext, wai-images)
27. Forms: labels, help text and errors linked to the field   (Standard: wcag-labels, wcag-error)
28. Language and direction set (Arabic right-to-left)   (Standard: w3c-dir)  -> see design-system/rtl-localisation

PROCESS
29. Automatic checks in the build (axe or similar)   (Practice)
30. Manual tests with keyboard and a screen reader (NVDA, VoiceOver, TalkBack)   (Practice)
31. Tests with disabled users when possible   (Research: nng-accessibility)
